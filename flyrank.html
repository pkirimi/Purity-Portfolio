Building a ranked content review queue with machine learning.

A machine learning project exploring how search intelligence signals can be used to identify content that may need review and prioritise what should be looked at first.

ROLE Machine Learning Intern
TASK Content Review Ranking
DATA 30,000 rows
MODEL Logistic Regression
01

THE PROBLEM

Which content deserves attention?

Search intelligence data can contain a large number of content items. Reviewing every page manually is inefficient, so the goal was to create a structured way to surface content that may need attention.

I approached the problem as a decision support task: use observable search performance signals to help prioritise content for human review.

OBJECTIVE Produce an ordered review queue rather than treating every content item equally.
02

PROBLEM FRAMING

Start with the decision, not the model.

There was no direct labelled outcome describing whether a piece of content actually required review. I therefore used is_declining as a proxy target for identifying potentially declining content.

This distinction matters. The model was not being presented as a definitive measure of content quality. It was being evaluated as a mechanism for supporting a review decision.

TASK Binary classification
TARGET is_declining
USE Decision support
03

DATA CONTRACT

Separate signal from context.

Before modelling, I separated the available fields into features, target, context and excluded fields. This helped make the modelling setup explicit and reduced the risk of using information that would not be available at prediction time.

FEATURES impressions_90d
clicks_90d
ctr
avg_position
sessions_90d
engagement_rate
LABEL / PROXY is_declining
CONTEXT client_id
content_id
report_date
EXCLUDED Future performance
Label derived fields
Decision scores
04

MODEL

A simple model with an honest baseline.

I chose Logistic Regression as the modelling approach because it provides a simple and interpretable classification baseline. The goal was not to maximise complexity, but to establish whether the selected signals provided useful predictive information.

TRAINING ROWS 24,000
TEST ROWS 6,000
MODEL Logistic Regression
TARGET is_declining
05

RESULTS

The numbers tell a mixed story.

On the test set, the model achieved high recall for the declining class, but its overall ability to distinguish between the two classes was weak.

ACCURACY 0.565
PRECISION 0.558
RECALL 0.946
F1 0.702
ROC AUC 0.515
INTERPRETATION

The model captured most of the declining cases, reflected by the 0.946 recall. However, the ROC AUC of 0.515 indicates that the model had very limited ability to separate declining from non declining content across thresholds.

06

ERROR ANALYSIS

Where did it go wrong?

The confusion matrix showed that the model identified many of the declining cases, but also classified a large number of non declining cases as declining.

The large number of false positives is important. A review queue built directly from this behaviour could send too much non declining content to human reviewers.

07

FEATURE INTERPRETATION

What did the model lean on?

Logistic Regression also provided an interpretable view of the relationship between the selected features and the predicted class.

CTR -0.182
CLICKS_90D -0.171
AVG_POSITION -0.087
SESSIONS_90D 0.055
IMPRESSIONS_90D 0.016
ENGAGEMENT_RATE -0.001

Coefficients are interpreted directionally within the fitted Logistic Regression model and should not be treated as causal effects.

08

WHAT I LEARNED

A reasonable score is not enough.

The most useful part of the exercise was not simply obtaining a model score. It was seeing how different metrics revealed different aspects of model behaviour.

A recall of 0.946 initially looks strong, but the confusion matrix and ROC AUC showed why it would be risky to judge the model using recall alone.

This reinforced an important ML engineering principle: the right model is not necessarily the most complex model. It is the model whose behaviour is useful for the decision it is supposed to support.
